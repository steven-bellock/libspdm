  • Each number is the function's own frame. It does not include the functions that it calls, so a call needs the sum of the frames along its deepest call chain.
  • Only library/ is measured. The cryptography and HAL functions that it calls, and the Integrator's callbacks, add their own frames.
  • The builds are Release builds (-Os) without link-time optimization, which STACK_USAGE turns off. With LTO, inlining across files can change the frames.
  • Frames over 512 bytes are highlighted. A number marked * is a frame that changes size by an amount that GCC cannot bound, and counts only its fixed part. GCC names the parts that it splits out of a function or specializes, such as .part.0 and .constprop.0, as functions of their own.
  • The numbers depend on the compiler and on the configuration macros, which size many local buffers.

Measuring a build

The all configuration on x64, for example. CMake needs a CRYPTO value, and that library's submodule, to configure, but building only the library/ targets compiles nothing from it. Each .su file lies next to its object file, so build/library holds only library/.

CFLAGS='-DLIBSPDM_CHECK_MACRO=1 -DLIBSPDM_DEBUG_LIBSPDM_ASSERT_CONFIG=3 -DLIBSPDM_RECORD_TRANSCRIPT_DATA_SUPPORT=1' cmake -B build -DARCH=x64 -DTOOLCHAIN=GCC -DTARGET=Release -DCRYPTO=openssl -DSTACK_USAGE=ON -DDISABLE_TESTS=1
cmake --build build --target spdm_common_lib spdm_crypt_lib spdm_requester_lib spdm_responder_lib spdm_secured_message_lib spdm_transport_mctp_lib spdm_transport_pcidoe_lib spdm_transport_storage_lib spdm_transport_tcp_lib
